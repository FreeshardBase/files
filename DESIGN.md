# DESIGN

The design guide "Daylight Instrument" (`docs/design-guide.md`) is binding. This file records only what the guide does not cover and where this app deviates.

## Tokens

`web/src/styles/tokens.css` and `web/src/styles/components.css` are copied from the guide bundle (`tokens.json` is canonical there). Do not edit values here; update the bundle and copy again. Fonts (Inter, IBM Plex Mono) come from `@fontsource` packages and are served by the shard, never from a font CDN.

## Icons

Line icons are SVG on a 24px grid with a 1.5px stroke, stored as data-URI custom properties (`--icon`) in `web/src/styles/app.css` and drawn through a CSS mask on the `.icon` class. The colour therefore comes from the theme tokens, not from the SVG. No emoji, no icon fonts.

## Dialogs

The guide has no dialog recipe. `<AppDialog>` (`web/src/components/AppDialog.vue`) is a `.fs-sheet`-like surface (surface tone, hairline border, sheet radius, no shadow) centred on a flat scrim of `--bg` at 70 %. The scrim separates the sheet by tone, not by elevation, so the "no shadows" rule holds in both themes. On phone width the sheet sits at the bottom edge and the action buttons share the row. Actions are outline buttons of equal weight: the one forward action takes the amber hairline (`.button.primary`), a destructive one the danger hairline (`.button.danger`). In the collision dialog "keep both" is the forward action and takes the initial focus, because it never loses data; "replace" is marked destructive. The "apply to all" checkbox is a native checkbox tinted with `accent-color: var(--data)` instead of the guide's custom `.fs-check`, so it keeps native keyboard and screen-reader behaviour without extra script.

## Selection, menus and drop targets

The guide has no recipe for these. A selected row takes a teal tint (`--data` at 9 %), never an amber fill, because amber is reserved for the one forward action. Row checkboxes use the native checkbox with `accent-color: var(--data)`, like the dialog checkbox. The row action menu is a sheet-like popup (surface tone, hairline border, tile radius, no shadow) behind a borderless icon button with a line "more" icon; on phone width the button is a 44 px touch target and the row is checkbox, name, menu, with size and date on a second line. A drop target (folder row or breadcrumb) gets a dashed teal hairline. While items are marked for moving or copying, "Move here"/"Copy here" is the forward action (`.button.primary`) and "Move to trash" the destructive one (`.button.danger`).

## Sidebar and trash

The guide has no navigation recipe. The source sidebar is a 200 px column on the surface tone with a hairline border; entries carry a line icon, and the current place is marked by a teal hairline at its left edge and teal text, never a fill. On phone width it becomes a row of tabs under the header with the hairline underneath. The trash view reuses the file-list table; each row has "Restore" (outline) and "Delete permanently" (danger hairline). "Empty trash" is a danger outline button, dimmed when the trash is empty. Every permanent delete asks first in `ConfirmDialog`, where "Cancel" takes the initial focus, because the safe choice should be the default. The Recent view (between "My storage" and "Trash", line clock icon) reuses the same table with name, location, changed time and one outline "Open folder" link per row; its empty state is a muted sentence of its own, never the folder's.

## Upload panel and drop zone

The guide has no recipe for progress or transfer lists. The upload panel is a sheet (surface tone, hairline border, sheet radius, no shadow) at the top of the main area, so it stays while the member navigates and never covers the list. Each file is a row: the name, its state in the mono face (for example "42 %"), and a 3 px progress line under it, teal (`--data`) on a hairline track (`--border`), with no fill animation and no glow. A failed row turns its state text and line to `--danger`. The failure summary is one box with a danger hairline: a count, the list "name: reason" and "Retry all" as the panel's one forward action (`.button.primary`). Cancel is a danger outline, pause, resume and retry are plain outlines. On phone width the actions wrap under the name and share the row. "Upload" stays the toolbar's forward action, and "Upload folder" next to it is a plain outline. Files dragged in from the desktop mark the folder area with the dashed teal hairline of a drop target and show a one-line hint in `--line`.

The transfer panel (#152) is the same sheet, directly under the upload panel, with the same row recipe: one row per job ("Copy “name” to My storage/folder"), its state in the mono face ("3 of 5 · 1.2 MB", "Done", "1 of 5 failed", "Cancelled"), and the 3 px teal line over the settled items. A job that ended with errors turns its state and line to `--danger` and lists the failed items with their reasons under its row in the small size, in `--danger`. Cancel is a danger outline while the job runs; "Clear finished" in the head is a plain outline. There is no forward action: the paste that started the job was it.

## Migration

The guide has no wizard recipe. "Move to shard" sits in the sidebar under "Cloud accounts" with a line icon (a cloud over a downward arrow onto a line). The wizard is one column up to 720 px with one step at a time under a numbered heading ("1. What to move"), which takes the focus when the step changes. The account is a native radio group tinted with `accent-color: var(--data)`. A folder is picked in a hairline box: the crumbs in `--line` (the current one in `--ink`) over a list of folder buttons with the folder line icon, separated by hairlines, 44 px high on phone width; opening a folder chooses it, and a sentence under the box says what was chosen. "Next" and "Start migration" are the forward action (amber hairline), "Back" a plain outline. The review is the details drawer's facts grid (from, to, files, folders, size) with "Counting …" or "at least" as a muted status line. The job's page uses the same column: the facts grid with the state in it, the 3 px teal progress line of the transfer panel, then "Summary" (verified files, size, failed), the failures in the panel's small `--danger` list, and "Export summary (CSV)" as a plain outline. "Delete verified originals …" is a danger outline under "Originals in the cloud", and it opens `ConfirmDialog`, where "Cancel" takes the focus. The cleanup's state and progress line follow under the same heading. On phone width the action buttons take the full row.

## Preview overlay

The guide has no viewer recipe. The preview is an `<AppDialog>` with `wide`: the same sheet, up to 1100 px wide and at most the viewport high, with the content scrolling inside and the actions always in view. On phone width it fills the screen apart from the scrim margin, and Previous, the position ("2 of 5", mono face, muted) and Next take their own row above Download and Close. Previous and Next stay focusable at the ends and are dimmed (`aria-disabled`), so the focus never drops out of the dialog. Images and video are contained to the sheet with the tile radius. Text sits in a `--bg` well with a hairline border in the mono face, and Markdown is set at a 72-character measure with links in `--line`. For an unsupported type or a failed preview, Download becomes the forward action (`.button.primary`). A PDF page is drawn on white with a hairline border in both themes, because it is a printed page and its own colours assume paper.

## Thumbnails and gallery

The guide has no media grid. A list row shows a 28 px thumbnail with a 4 px radius in place of the file icon. The gallery is a grid of tiles at least 160 px wide (104 px on phone width): each tile is surface tone with a hairline border and the tile radius, a square image cut to fill (`object-fit: cover`) on `--bg`, and the name in one line under a hairline. A file without a thumbnail, and a folder, show their line icon at 40 px in the same square. Hover turns the hairline teal (`--line`); there is no shadow and no zoom. The "List / Gallery" toggle is two outline buttons; the current view takes the teal hairline and teal text, like the current place in the sidebar, never a fill, because amber stays the one forward action (Upload).

## Search

The guide has no search or combobox recipe. The field sits in the header right of the app name: a `.fs-input` with a muted line magnifier inside its left edge, at most 480 px wide; on phone width it takes its own full-width row under the name and is a 44 px touch target. Results open in a sheet-like popup under the field (surface tone, hairline border, tile radius, no shadow). Each source is a group with an uppercase label in the label style; an option shows its line icon, the name, and the folder it is in as a muted second line. The active option (arrow keys or hover) is marked like a selected row: a teal hairline on its left edge and the 9 % teal tint, never amber. Below the results come muted notes: "searching", the empty-state sentence, "more matches" per capped source, and a source that could not be searched in `--danger`.

## Sharing and details

The guide has no recipe for a picker, an access list or a drawer. The share dialog is a plain `<AppDialog>`: the member field is a `.fs-input` whose matches open in a list under it, styled like the search popup (surface tone, hairline border, tile radius, no shadow); the active or hovered member takes the teal left hairline and the 9 % teal tint, never amber. The access level is two native radios tinted with `accent-color: var(--data)`, like the dialog checkbox. "Share" is the dialog's one forward action (amber hairline); "Remove access" per member is a danger outline, "Close" a plain outline. "Who has access" is a small heading over rows separated by hairlines: the name, the access in muted small text, the button. The details drawer is the same sheet docked to the right edge at full height and 380 px wide, with only a left hairline and no radius, on the same flat scrim; on phone width it is a bottom sheet with the top corners rounded. Its facts are a two-column grid with muted labels; "Share …" is its forward action. "Shared with me" sits in the sidebar between Recent and Trash with a line "people" icon and reuses the trash table (name, shared by, access, date, one outline "Open", "Download" or "Remove from list" per row). In a read share the folder view simply leaves out what cannot be done (upload, rename, move, copy, trash), rather than showing dimmed controls.

## Public links

The guide has no recipe for links or a page for visitors. In the share dialog, "Public links" follows "Who has access" with the same small heading and hairline rows: the label, a muted line with password, expiry and downloads ("0 of 1 downloads"), the address in a read-only `.fs-input` in the mono face (it is a machine string), and "Copy", "Edit" as plain outlines and "Revoke" as a danger outline. "New public link" is a plain outline, because "Share" stays the dialog's one forward action; inside the open link form, "Create link" or "Save" takes the amber hairline. The form sits under a hairline in the same dialog instead of a second dialog, so the focus never leaves the share dialog. The share page for visitors has the app header without search or sidebar and one centred column up to 640 px: an uppercase label ("Shared file"), the name as the view title, then either the password field with "Open" as the forward action, or the facts grid of the details drawer with "Download" as the forward action and "Open preview" as a plain outline. A refusal (limit reached, expired) is a box with a danger hairline, never a fill. On phone width the page's buttons take the full row and are 44 px high.

The guide has no recipe for favourites (#155). The star is a line star on the icon grid: outlined in `--ink-muted` in a borderless icon button next to the row's menu button (a 44 px touch target on phone width, where the row is checkbox, name, star, menu), and filled in the teal line colour once the item is a favourite, never amber, because amber stays the one forward action. The details drawer has the same star as a plain outline toggle before "Share …". "Favourites" sits in the sidebar before Recent with the outlined star. Its view reuses the Recent table (name, location, "Open" and "Remove" as plain outlines); a favourite whose source is gone says "Unavailable" in small `--danger` text under its location and has no "Open".

## App icon, offline banner and share target

The guide has no app icon. The PWA icon (`web/public/icons/`) is the app's own line folder glyph (the `icon-folder` path, 1.5 px stroke on the 24 px grid, scaled) in `--line` on the paper ground `--bg`, with a hairline `--border` edge and the sheet radius; the maskable variant is full-bleed paper with the glyph inside the safe zone. No amber, since the icon is no forward action. The theme colour is `--surface` (light) and the dark surface (dark), so the installed app's title bar matches the header.

Offline, a one-line banner sits under the header: a line "cloud crossed out" icon and muted small text on the surface tone with a hairline underneath, no fill and no danger tone, because offline is a state, not an error; the data area below still shows the "No connection" alert with "Try again".

"Save shared files" uses the migration wizard's column: a muted intro, the shared files as a hairline list with sizes in the mono face, the folder picker, the chosen target as a sentence, then "Save here" as the one forward action (`.button.primary`) and "Discard" as a plain outline (the files are only in this browser and can be shared again).

## Language and theme

The guide has no settings recipe. Language and theme sit at the top of Settings, each a group of native radio buttons under a `.fs-label` legend, tinted with `accent-color: var(--data)` like the share dialog's radios, so they keep native keyboard behaviour (arrow keys move and choose). There is no save button: a choice is saved at once, confirmed in the status line, and a refusal is shown in the danger-coloured alert line. The language names are written in their own language ("Deutsch (Sie)", "English") and carry their `lang`. The theme sets `data-theme` on `<html>`; "Same as the device" follows `prefers-color-scheme`. `color-scheme` follows the theme, so native controls and scrollbars match it.

## Deviations

None beyond this: the file list is a table (`FileList.vue`, a real `<table>`), because name, size and modified date are columns the user compares. The guide has no list recipe.
